## Project Overview
`server-forge` is an Infrastructure-as-Code (IaC) repository for provisioning and managing a fleet of AI training servers. Core philosophy: **fully reproducible, script-driven server configuration** — no manual data backup, only configuration scripts and version control are used to rebuild any node from scratch.

## Per-Node Configuration
Each node directory contains the machine's complete environment:
- `hardware-info.txt` — full hardware report generated by `scripts/lib/hardware-info.sh`
- `README.md` — machine-specific configuration (OS, drivers, roles, maintenance log)
- Refer to individual node directories for all machine-specific details.

## Configuration Management Principles
1. **Everything as code** — all machine configuration is version-controlled.
2. **Back up configs, not data** — all data volumes (Docker images, GitHub repos,
   databases, LLM models) are ephemeral and rebuildable via configuration code
   maintained in this repository. Only the provisioning scripts are version-controlled;
   the data they produce is not.
3. **Leave headroom** — always reserve unallocated capacity for online expansion.
4. **Persist configs** in each node's directory and apply them to system paths during provisioning.
5. **Temporary files** generated during processing (logs, intermediates) must be written
   to the project `tmp/` directory, never to system `/tmp/` or working directory root.

Troubleshooting is documented per-node in `nodes/<hostname>/README.md`.

## Machine Discovery

Before any operation on a managed node, run:
```bash
source scripts/lib/discover.sh
```
This auto-detects the current machine and exports environment variables pointing to
its config directory under `nodes/`. If the machine is not yet registered, it prompts
to create one by copying an existing similar node.

**Important**: If the user does not explicitly specify a target machine, always run
`source scripts/lib/discover.sh` first to auto-discover the current environment and
operate on the detected node.

## Agent vs User Responsibilities

This project manages bare-metal servers. Many operations require physical access,
root privileges, or irreversible system changes. The boundary is:

### Agent Responsibilities (read-only, project-scoped)
- Run `source scripts/lib/discover.sh` to detect the current machine
- Run `bash scripts/lib/hardware-info.sh` to collect hardware information
- Read and edit files within the project directory (nodes/, CLAUDE.md, inventory/, benchmark/)
- Run benchmark scripts
- Analyze hardware reports and document findings

### User Responsibilities (physical access or root required)
- All provisioning steps documented in `nodes/<hostname>/README.md`
- OS installation and partitioning
- Network configuration (Ethernet, WiFi)
- Package installation (`apt install`, driver installation)
- System-level configuration (`/etc/` files, GRUB, kernel modules, Docker daemon)
- Any `sudo` command that modifies system state

Agent permissions are enforced in `.claude/settings.json`.

> **Project spirit**: Every fix becomes a config or a doc page, so the next server is forged faster and more reliably.
