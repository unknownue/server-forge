── Measurement caveat (important) ──────────────────────────────────────────
  A naive streaming client under-reports throughput here: reading SSE chunks
  one at a time and timing per-chunk yields ~36 tok/s on the SAME run where the
  engine reports 75-103 tok/s. Use non-streaming `usage.completion_tokens`
  divided by elapsed time, or the engine's own gen-throughput log, not a
  per-chunk streaming timer. The first measurements in this session were wrong
  for exactly this reason and were corrected.

── Build problems solved to get here (all now scripted) ────────────────────
  1. atomicAdd ambiguity: the fork's compat.cuh defines atomicAdd(half2*,half2)
     under USE_ROCM, which now collides with ROCm 7.14's own hip_fp16.h
     overload. Routed 10 call sites through the file's explicit helpers.
     NOTE: gptq_kernel.cu is the file actually compiled; gptq_kernel.hip is a
     stale sibling not in setup_rocm.py's source list.
  2. Wrong GPU arch: setup_rocm.py reads AMDGPU_TARGET (singular) and otherwise
     auto-detects via torch. With no GPU visible during `docker build` it fell
     back to gfx942 and produced a library with none of the gfx1100 kernels,
     failing at runtime with hipErrorInvalidDeviceFunction. Fixed by exporting
     AMDGPU_TARGET=gfx1100.
  3. gptq_gemm arity: the op schema declared use_v2_format with a default, so
     torch's binding exposed 7 positional args while the engine passes 8
     ("takes 7 positional arguments but 8 were given"). Removed the default.
  4. Stale sgl_kernel Python wrappers: only common_ops*.so was being copied
     into the venv, so the base image's older gemm.py (7-arg gptq_gemm) shadowed
     the fork's correct 8-arg wrapper. Fixed by copying the fork's sgl_kernel
     *.py into site-packages too.
  5. rdna_ar_ext missing: without pre-building scripts/rdna_ar/rdna_ar_ext.py the
     worker logs "failed to load rdna_ar_ext" and silently falls back to NCCL.
  6. Dependency/packaging: sglang installed with --no-deps (its declared deps are
     CUDA-oriented), with the non-CUDA runtime set installed from
     sglang-runtime-deps.txt. torch/torchaudio/torchvision are pinned OUT of
     that list, otherwise pip replaces the ROCm torch with CUDA wheels and
     torchaudio fails to load. PyPI pinned to the Tsinghua mirror.
